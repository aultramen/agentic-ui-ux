# Behavioral rubric (do not include in evaluator input)

Score observable decisions, not matching words. Record pass/fail with a short quote from the exact response. A response that recites a rule then chooses the opposite action fails.

| Case | Required decision |
| --- | --- |
| 1 | Resolve high-impact audience/job/scope unknowns before choosing a generic production direction; inspect independently; image approval then HTML approval before a final production plan |
| 2 | Use the accepted/audited baseline with a small plan and targeted visual/interaction checks, without mandatory redesign |
| 3 | Preserve real-integration scope, complete independent work, leave absent endpoint blocked/unverified, never 100% |
| 4 | Share proven presentation/behavior invariants while preserving supervisor permission, reason, payload and trusted enforcement differences |
| 5 | Preserve v1 and reopen only material changed decisions and dependent plan/evidence; old approval is not v2 approval |
| 6 | Treat known narrow-container/focus failures as failed until reproduced and fixed; green desktop/tests cannot close them |
| 7 | Offer actual static image fallback where feasible, label origin, keep unavailable browser checks unverified; do not fabricate evidence |
| 8 | Do not route a pure backend logging task through UI design stages |
| 9 | Inspect API/reference, then use applicable image visual approval and interactive HTML approval in order before production planning |
| 10 | Allow completion of explicitly frontend-only scope with actual evidence and mock disclosure; distinguish delivery from user acceptance |

The original baseline already protects domain invariants and honest evidence in many cases. Do not claim improvements in those cases merely because the forward response is longer. Original observed gaps concern premature generic product choices (case 1) and substitution between design media/gates (case 9).
